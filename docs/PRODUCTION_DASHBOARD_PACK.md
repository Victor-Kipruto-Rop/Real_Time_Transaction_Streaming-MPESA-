# Production Dashboard Pack

This dashboard pack is the production operations view for the M-Pesa event pipeline. It provides monitoring for runtime health, transaction throughput, duplicate protection, and data quality.

## Included dashboards

- [grafana/dashboards/live_operations.json](../grafana/dashboards/live_operations.json) — real-time ingestion, throughput, and freshness
- [grafana/dashboards/executive_command_center.json](../grafana/dashboards/executive_command_center.json) — leadership summary and business KPIs
- [grafana/dashboards/fraud_risk.json](../grafana/dashboards/fraud_risk.json) — risk, anomaly, and high-value review monitoring
- [grafana/dashboards/customer_intelligence.json](../grafana/dashboards/customer_intelligence.json) — customer behavior and value segmentation
- [grafana/dashboards/data_quality.json](../grafana/dashboards/data_quality.json) — quality gating, duplicate checks, and model freshness

## Primary operational views

### Live operations

Use this dashboard for the day-to-day control plane:

- event ingestion rate
- transaction volume and value
- freshness of data landing in the warehouse
- duplicate checks and malformed events
- latest confirmed transaction activity

### Data quality

Use this dashboard to monitor:

- rows missing key identifiers
- invalid or negative amounts
- raw-vs-staged mismatches
- model freshness drift
- duplicate IDs flagged in raw input

### Fraud and risk

Use this dashboard to monitor:

- critical/large value events
- suspicious night-hour activity
- high-velocity customer patterns
- customer review queue and risk exposure

### Executive summary

Use this dashboard to communicate:

- total value processed today
- transactions and customer adoption trends
- average ticket and revenue movement
- top account-reference performance by value and activity

## Dashboard operating expectations

- Grafana should use the `mpesa-postgres` datasource and remain aligned with the live warehouse schema.
- Each dashboard should be reviewed before production releases.
- The live operations dashboard is the first stop during an incident.
- Dashboard health and data freshness should be part of release sign-off.

## Dashboard generation

The dashboard definitions are generated by [dashboards/grafana_dashboards.py](../dashboards/grafana_dashboards.py).

To validate the generated dashboards:

```bash
python3 dashboards/grafana_dashboards.py --check
```

This ensures the dashboards remain structurally valid and are wired to the expected Postgres datasource.
